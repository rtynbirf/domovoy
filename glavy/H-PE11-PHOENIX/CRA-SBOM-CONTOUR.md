# CRA-SBOM-контур роя · поле `sbom_ctx` в SEALS.jsonl

EU Cyber Resilience Act: reporting obligations применяются с 11.09.2026 — активно
эксплуатируемые уязвимости и тяжёлые инциденты репортятся в ENISA за 24 часа;
полные обязательства (включая SBOM) — с 11.12.2027. Корень доверия роя —
`SEALS.jsonl`, append-only хеш-цепь пломб (канон — `PROVEN/SEALS-CANON.md`).
Контур делает CRA метрикой: пломба реакции несёт SBOM-след, SLA — гейт.

## Поле `sbom_ctx` (аддитивно, старые записи не трогаются)

Каждая НОВАЯ запись SEALS.jsonl может нести поле `sbom_ctx`:

```json
{"deps_manifests": ["<путь/к/манифесту-зависимостей>", "..."], "checked": "OSV/Dependabot", "note": "<что пломбируем>"}
```

- `deps_manifests` — какие манифесты зависимостей сверены на момент пломбы (пути в репо; пустой список = честный ноль);
- `checked` — чем сверяли (например `OSV/Dependabot`), одна строка, без фантомов;
- `note` — что именно пломбируем, человекочитаемо.

Пример записи цепи (иллюстрация формата; `...` — существующие поля записи):

```json
{"...": "...", "sbom_ctx": {"deps_manifests": [], "checked": "OSV/Dependabot",
 "note": "CRA-реакция на vuln-событие 2026-11-08 из reports/cra-events.jsonl"}}
```

## Связь с 24-часовым SLA

- События живут в `reports/cra-events.jsonl`, формат `{"date","source","summary"}` (см. `reports/README.md`).
- `tools/cra_sla.py`: событие с датой ≤ сегодня−2 (24 ч уже не могли хватить — время суток неизвестно),
  без записи SEALS.jsonl с датой ≥ даты события = 🔴 инцидент; exit 1 — честный гейт.
- Пломба-реакция с `sbom_ctx` закрывает событие: сверка → пломба ≤ 24 ч.
- Воркфлоу `.github/workflows/cra-sla.yml` (вторник 06:00 UTC): selftest + живой прогон.

## Приёмки

1. `python3 tools/cra_sla.py --selftest` → зелёный и красный сценарии, «SELFTEST OK».
2. Живой прогон: журнала нет → событий нет → 🟢, exit 0; событие старше 24 ч без пломбы → 🔴, exit 1.
3. Аддитивность: `jq '.sbom_ctx' SEALS.jsonl` — поле у новых записей, старые записи цепи не тронуты.
