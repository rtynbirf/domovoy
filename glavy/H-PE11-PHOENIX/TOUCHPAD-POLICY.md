# ПОЛИТИКА ТАЧПАДА — PHOENIX-11 v1.3

**Уровень:** решение Хозяина (обязательное)
**Действует с:** v1.3
**Формулировка Хозяина:** «Тачпад я не юзаю от слова совсем. Стандартный ставь:
родные дрова весят духуя, а толку от их настроек нулевые».

## Правило
1. **СТАНДАРТНЫЙ in-box драйвер Microsoft** — единственный путь для тачпада.
   В базе boot.wim уже есть всё необходимое:
   - `/Windows/INF/hidi2c.inf` — HID over I2C
   - `/Windows/INF/iaLPSS2i_I2C_*.inf` (BXT_P/CNL/GLK/SKL и др.) — Intel Serial IO I2C (in-box)
   - HIDClass/hidusb и стек мыши — in-box
2. **Вендорные паки Synaptics / ELAN / ALPS / Cirque — ЗАПРЕЩЕНЫ.** 0 байт.
   Не добавлять ни в WIM, ни на носитель, ни в whitelist drvload.
3. Тачпад работает как **обычная мышь** (перемещение, клики, скролл — по
   возможностям in-box драйвера). Жесты мультитача — НЕ входят в область
   поддержки и не считаются дефектом (ЭВ.1: [--] честно).
4. Проверка при дымах/донах: тачпад двигает курсор после `wpeinit` — достаточен.
   Настройки/панели вендора — не нужны и не должны появляться.

## Почему (инженерия)
- Вендорные паки Synaptics/ELAN — десятки мегабайт на каждый класс устройств.
- В WinPE их панели настроек всё равно мертвы (нет оболочки), то есть
  «толку от их настроек нулевые» — буквально.
- In-box стек покрывает PTP/I2C-тачпады достаточным минимумом: курсор + клик.
- Хозяин тачпад не использует от слова совсем — значит, оптимальный вес = 0 байт
  вендорного кода.

## Проверено фактом (v1.3, ЭВ.1)
- Поиск по образу: `synaptics|elan|touch|alps|cirque` → вендорных пакетов НЕТ.
- В образе только in-box Microsoft/Intel I2C-инфраструктура.
- v1.2 уже была чиста по тачпаду; v1.3 фиксирует это как политику.

## Для будущих изданий (v1.4 ВАЛЬКИРИЯ)
Whitelist драйверов под новое железо собирается по профилю станции
(collect-станция), НО пункт про тачпад из whitelist исключается всегда —
эта политика старше любой матрицы поддержки.
