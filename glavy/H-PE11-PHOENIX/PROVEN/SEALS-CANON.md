# Канон SEALS.jsonl · хеш-цепь пломб (П-09 / ПРЕДЛОЖЕНИЕ-40)

Журнал пломб — append-only JSONL. Каждая запись ссылается на предыдущую:
`prev_sha256` записи N == `sha256_self` записи N-1. Голова цепочки —
`sha256_self` последней записи: одно число, тампер-очевидность всего журнала
(любая правка старых записей внутри канона v2 ловится verifier-ом; голова
публикуется в summary воркфлоу `evidence-chain`).

## Канон v1 (наследие, записи seq 1–10)

Поля: `bytes, created_at, kind, note, prev_sha256, seq, sha256_self,
sha256_worklog, subject`. `sha256_self` ссылался на ворклог вне этого
репозитория (полимат-хаб), поэтому из репо воспроизводима только **линк-цепь**
(verifier проверяет сшивку prev/self и порядок seq, но не содержимое).
Верификатор честно помечает такие записи `legacy` — это не рана, а граница.

## Канон v2 (с записи seq 11, волна ×4)

Запись дополнительно несёт `"canon":"v2"` и **сам-хеш выводим из содержимого**:

```
payload        = запись БЕЗ поля sha256_self
canonical      = json.dumps(payload, sort_keys=True, ensure_ascii=False,
                            separators=(',',':')).encode('utf-8')
sha256_self    = sha256(canonical)
```

Любой байт записи (нота, хеш ворклога, поля evidence) при правке ломает
`sha256_self` — verifier различает роды ран: `link` (разрыв цепи), `tamper`
(несоответствие сам-хеша содержимому), `seq`, `json`, `genesis`.

Инструменты: `tools/verify_seals.py` (verifier), `tools/seal_append.py`
(append-only пломба: fail-closed на разрыве, prev = текущая голова).
Доп. поля свидетельств допускаются (например `evidence_sha256_iso`) — канон
v2 их хеширует наравне с базовыми.

## Сшивка с наследием

`prev_sha256` записи 11 = `sha256_self` записи 10 (`916320d4…`) — цепь
непрерывна через смену канона; старые записи не переписываются никогда
(append-only), их содержимое охраняется линк-цепью и внешними копиями хаба.
