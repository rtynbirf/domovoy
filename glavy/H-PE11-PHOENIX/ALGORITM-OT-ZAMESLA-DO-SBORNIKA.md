## ФАЗА 0 — ЗАМЫСЕЛ ЧЕЛОВЕКА (нулевая точка всего алгоритма)

**ЗАЧЕМ.** Человек (Хозяин) хочет на своём старом, но живом ПК:
1. Современную Windows 11 (ветка 26H1, сборка 26300.9807 — «PHOENIX-ALPHA»), потому что
   железо работает, а выбрасывать рабочую станцию из-за TPM-ценза он не согласен.
2. Инструментальную WinPE-флешку («Стрелец», F: STREL на Ventoy), чтобы машина была
   реанимируемой: загрузиться с неё можно даже когда Windows мертва, внутри — MemTest86+,
   BurnInTest-инструменты, утилиты разметки и восстановления.

**СТАТУС ФАЗЫ:** `[БОЙ]` — замысел сформулирован и зафиксирован; WinPE-флешка уже существует
и грузится (Ventoy Legacy подтверждён загрузками), желаемая сборка определена (26H1 26300.9807).

**ВАЖНОЕ ОГРАНИЧЕНИЕ, заданное замыслом:** железо Legacy BIOS + MBR, значит весь конвейер
(ISO → флешка → установка) обязан жить в CSM-режиме. Никаких UEFI-only фокусов.

## ФАЗА 2 — ВЫБОР БАЗИСА (какой образ Windows вообще добываем)

**ЗАЧЕМ.** Нужен ISO 26H1, из которого мы сделаем свой сборник. Базис — фундамент: ошибки
здесь обесценивают всё дальше.

**ЧТО ДЕЛАЕМ:**
- Базис выбран: PHOENIX-ALPHA-0.1 = Windows 11 26H1, сборка **26300.9807**, язык RU, x64.
- Кандидат-альтернатива «26100.1 WILLIAM_v2 с трекера» — **ОТКЛОНЕНА** (решение задокументировано):
  1) бисекция требует неизменного базиса (Law 1) — чужой образ делает исход нечитаемым;
  2) это деградация базиса (26100.1 старше 26300.9807 на 2+ года без единого кумулятива);
  3) на i3-2120 стоковый 26100.1 без обходов TPM/CPU не встанет, а обходы вшиты в НАШ autounattend —
     Rufus-галочки = ещё одна неконтролируемая переменная.
- Резерв на случай краха бисекции (0.3): официальная добыча через FIDO/UUP —

## ФАЗА 3 — ДОСТАВКА БАЗИСА НА ПК (части → склейка → хеш)

**ЗАЧЕМ.** ISO весит ~4.3 ГиБ, каналы качают с обрывами. Решение: раздача релизом GitHub
**частями по 463 393 178 Б** + манифест хешей. Каждый кусок можно докачать отдельно (curl -C -),
а после склейки Law 4 докажет целостность до байта.

**ЧТО ДЕЛАЕМ (это и есть `scripts/PHX-GLUE-BISECT.bat`, v5 — подробно раскомментирован):**
1. Скачать 10 частей + `SHA256SUMS.txt` в одну папку (релиз `phoenix-alpha-0.2-bisect`, id 424174280).
   Обрывы не страшны: `curl -C -` продолжает с места разрыва.
2. Батник сам находит части (в своей папке / в родителе / в Downloads) — не надо угадывать пути.
3. Переименование `part00..09` → 7-Zip-имена `.001..010` (7-Zip понимает только трёхзначные хвосты).
4. Проверка РАЗМЕРОВ каждой части против эталона: 9 × 463 393 178 Б + последний 463 393 174 Б.
   Размеры расходятся → качай часть заново, не клей.
5. Склейка 7-Zip (Extract из .001) либо `copy /b .001+.002+...+.010 ISO` — байтовая конкатенация.
6. Финальная сверка: размер целого = 4 633 931 776 Б; SHA256 = `12332871ac64bc2fb21b0139a927f6ea8972378004ebcd5d5aaaac3c8ccfd43a`.

**КАК УБЕДИТЬСЯ:** SHA256SUMS.txt содержит хеш каждой части И хеш целого ISO.
`certutil -hashfile файл SHA256` → строка совпала = Law 4 закрыт. Не совпала — ошибка
в этой части, перекачать её, а не весь набор.

**СТАТУС:** приём целиком `[БОЙ]`: alpha-0.1 (5 частей) в песочнице докачана с resume,
склеена (4 292 575 232 Б), SHA256 сверен, 5/5 MATCH; 0.2-BISECT разлил те же приёмы
на 10 частей. Батник v5 `[ГОТОВ]` — ждёт прогона у Хозяина на установке №3.

**ПРОВЕРЕННЫЙ ФАКТ СКЛЕЙКИ [БОЙ]:** SHA256 собранного в песочнице alpha-0.1.iso = `612ea530…`
(MATCH провенансу), 1452 файла дерева извлечены — конвейер «части→ISO→дерево» работает.

## ФАЗА 4 — ХИРУРГИЯ ОБРАЗА (из мёртвого стокового ISO — живой сборник)

**ЗАЧЕМ.** Стоковый образ не встанет на i3-2120 (TPM/CPU-ценз) и не содержит дров ASMedia/VIA.
Сборник = стоковый образ + четыре правки, БЕЗ трогания install.wim/boot.wim/bootmgr.

**ЧТО ДЕЛАЕМ (конвейер: дерево ISO → правки → пересборка):**
1. Извлечь всё дерево ISO (pycdlib; 1057 файлов у alpha-0.1).
2. **autounattend.xml v4-BISECT** на корень носителя — мозг автоматизации:
   - bypasses TPM/CPU/RAM/SecureBoot (иначе setup завернёт i3-2120 на корню);
   - locale ru-RU, ComputerName, скрытия OOBE-страниц;
   - DriverPaths → C:\Drivers (offlineServicing/windowsPE);
   - **НЕТ** авто-юзера, НЕТ AutoLogon, НЕТ пароля на носителе (аудит: пароль был найден
     открытым текстом в alpha-0.1 и вырезан — Law 5).
3. **Драйверы DP_6ORMAN** ($OEM$ → C:\Drivers): 95 INF / 106 .sys — SATA AHCI 1C02, SNB,
   ASMedia xHCI, VIA HD Audio, Realtek GbE, H61 LPC, ME. Кит принят по Law 4:
   60 508 186 Б, SHA256 `84ad85045e7e902df2c51c8a749aecaea5fffc97aad5a2293c242bf9845ff35e`.
   $WinPEDriver$ ВЫБРОШЕН (PE-фаза доказанно живёт без дров; с Ventoy после ребута медиа
   недоступна — это проверенный факт).
4. **SetupComplete.cmd = ТОЛЬКО драйверы**: `pnputil /add-driver C:\Drivers\*.inf /subdirs /install`,
   лог в C:\PHX\logs. Твикпак и аудит НЕ стартуют автоматом (бисекция требует голого setup).
5. **Патчи аудита 001 (CONTROL-меню) и 002 (PHX-RUN)** применены к киту C:\PHX\bin.
6. Пересборка ISO pycdlib: El Torito BIOS (etfsboot 8×512, seg 0x2000) + UEFI (efisys 2880×512) —
   рецепт оригинала; joliet-лимит 64→106 (monkeypatch, эквивалент `-joliet-long`);
   глубина каталогов ≤7 → Drivers сплющены до класса; кириллица → ASCII-транслит + hash-суффиксы.

**КАК УБЕДИТЬСЯ:** SHA256 итогового ISO; стрим-хеши нетронутых гигантов (install.wim
3 504 443 000 Б, boot.wim 510 584 393 Б, bootmgr) MATCH провенансу базиса; дифф дерева правок.

**СТАТУС:** `[БОЙ]` — 0.2-BISECT собран: **4 633 931 776 Б, 1452 файла,
SHA256 = `12332871ac64bc2fb21b0139a927f6ea8972378004ebcd5d5aaaac3c8ccfd43a`**,
стрим-хеши MATCH; автопроверка каждого шага пайплайна.

## ФАЗА 6 — НОСИТЕЛЬ (из ISO — загрузочная флешка для Legacy-железа)

**ЗАЧЕМ.** Биос старый: грузится только Legacy с MBR-флешки. Неправильная схема записи = чёрный экран.

**ЧТО ДЕЛАЕМ:** Rufus → выбрать ISO 0.2-BISECT → схема разделов **MBR** → целевая система
**BIOS (или UEFI-CSM)** → файловая система **NTFS** → START (флешка будет стёрта).

**КАК УБЕДИТЬСЯ:** флешка грузится Legacy на целевом ПК и доезжает до меню установки.

**СТАТУС:** `[БОЙ]` — этот же приём использован для alpha-0.1, флешка грузилась и установка
дважды стартовала (включая PE-фазу с сетью и видимым диском).

## ФАЗА 7 — ПОДГОТОВКА ДИСКА (снос огрызка, защита данных)

**ЗАЧЕМ.** Огрызок System 100 МБ (P1) — старая загрузочная ступень. Если её не снести,
установщик может запутаться в чужом BCD (установка №1 падала c000000f именно в этой зоне).
Чистая площадка = свежий System + свежий BCD, созданные установщиком.

**ЧТО ДЕЛАЕМ (`scripts/PHX-DISK-PREP.bat`, v2.0 — раскомментирован):**
1. Показывает карту Диска 0 ДО (rescan → select disk 0 → list partition).
2. Ожидаемая карта сверяется с эталоном разведки: P1=100 МБ System, расширенный 872 ГБ,
   E: Data 850 ГБ, F: STREL 21 ГБ. Не совпала → Enter = ABORT.
3. `detail partition` P1 — криминалистика перед удалением (лог).
4. Подтверждение 1: `Y`. Подтверждение 2: ввести слово `DELETE` руками (Law 2: молча ничего).
5. `delete partition` только на P1; карта ПОСЛЕ в лог.
6. Итог: ~60 ГБ нераспределённого места; E:/F: и Диск 1 не тронуты.

**КАК УБЕДИТЬСЯ:** лог `PHX_DISKPREP_*.txt` (BEFORE/DETAIL/DELETE/AFTER), а на живом диске —
«Управление дисками»: P1 исчезла, E:/F: целы.

**СТАТУС:** `[ГОТОВ]` — ждёт прогона №3 на реальном железе.

## ФАЗА 8 — ДИАГНОСТИКА ЖЕЛЕЗА (RAM — главный подозреваемый среды)

**ЗАЧЕМ.** WHEA-записи указывают на память. Если RAM битая, ЛЮБАЯ сборка будет умирать
случайными способами — и бисекция станет невозможной. Поэтому память проверяется ДО третьей
установки, и её вердикт — арбитраж всей ветки гипотез.

**ЧТО ДЕЛАЕМ:**
- MemTest86+ — из меню Стрельца (F: STREL), качать не нужно.
- BurnInTest — уже настроен: WHEA=Yes, ≥5 циклов (RAM.log / HTML-отчёт — доказательства).

**КАК УБЕДИТЬСЯ:** RAM.log без ошибок = железо снято с подозрения; ошибки = ветка «чистая память
под замену», бисекция останавливается до ремонта.

**СТАТУС:** `[В КУРСЕ]` — тесты крутятся/назначены, вердикта нет.

## ФАЗА 9 — УСТАНОВКА (главный бой)

**ЗАЧЕМ.** Собранное должно встать. Это и есть приёмочная сдача сборника.

**ЧТО ДЕЛАЕМ:**
1. Загрузка Legacy с флешки (0.2-BISECT).
2. В установщике выбрать **НЕЗАНЯТОЕ ~60 ГБ на Диске 0** (System+C: установщик создаст сам).
   E: Data и F: STREL НЕ ТРОГАТЬ.
3. OOBE: юзера создать РУКАМИ (локальная учётка) — пароля на носителе нет (Law 5).
4. SetupComplete сам поставит дрова из C:\Drivers (pnputil), лог в C:\PHX\logs.

**КАК УБЕДИТЬСЯ:** рабочий рабочий стол на C:, C:\PHX\logs\*.log без ошибок, E:/F: на месте,
диспетчер устройств без жёлтых знаков (или с известными некритичными).

**СТАТУС:** `[В КУРСЕ]` — бисекция: alpha-0.1 дважды доезжала до specialize (PE-фаза жива:
сеть выдаёт IP, диск виден, 78 устройств PnP прошли) и умирала жёстким обрывом;
0.2-BISECT — контролируемый изолированный прогон №3, точка невозврата specialize.
